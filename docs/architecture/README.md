# Rush Rivals — Architecture (Phase 1 + Phase 2)

## 3D run renderer (primary since Phase 2 refinement)
- `src/game/three/ThreeRenderer.ts`: a three.js scene that **only reads** `GameEngine` state. The pure TS engine remains the single source of truth.
- **Runner:** the Quaternius UAL1 CC0 rigged mannequin.
  - The GLB is embedded as base64 in `three/runnerModel.ts` and generated by `art_src/strip_glb.mjs` (793 KB).
  - An `AnimationMixer` crossfades between clips, driven by wall-clock time:
    - Jog/Sprint, with timeScale tied to speed.
    - Jump_Start/Loop/Land.
    - Roll, time-fitted to `slideTime`.
    - Death01.
  - The runner leans and yaws on lane changes.
  - Per-character outfit: vertex colours painted from the skinned bind pose (skin, top, hem accent, pants/shorts, shoes), plus hair, hood and headband meshes parented to the Head bone.
- **World:**
  - Chase camera that rises on roofs.
  - Rails and instanced sleepers.
  - Pooled trains with window bands, headlights and roofs, plus wedge ramps. Moving trains get blinking red lights and a marker.
  - Barriers.
  - Instanced spinning coins and glowing pickups.
  - Instanced buildings and lamps, with per-world palettes, a sky dome gradient and fog.
  - Blob shadow.
- **Graphics Low/Medium/High** maps to:
  - pixel ratio (web only; the native expo-gl drawable size is fixed);
  - antialias;
  - shadow maps (High only);
  - fog/draw distance and building density.
- `src/game/three/Run3DView.tsx` uses the standard `expo-gl` path: `GLView` → `THREE.WebGLRenderer({ context: gl })`, with `gl.endFrameEXP()` called on native. If GL initialisation fails or times out (6 s), `RunScreen` falls back to the Skia 2D renderer below.
- `glb` is not in Metro's default `assetExts`, and `metro.config.js` is protected, so the model ships as base64.

## Stack
- **Game client:** Expo SDK 58 (React Native 0.88, expo-router), at `/app/mobile`.
- **Rendering:** `@shopify/react-native-skia` 2.x. Each frame, a JS-thread `requestAnimationFrame` loop
  (1) steps the pure-TS simulation and (2) records one `SkPicture` (road, scenery, sprites) that it writes into a
  Reanimated `SharedValue` rendered by `<Canvas><Picture/></Canvas>`. React only re-renders HUD text (~10 Hz).
  On web, CanvasKit (`public/canvaskit.wasm`) is loaded during the splash (`LoadSkiaWeb`) and the run screen is
  code-split behind `WithSkiaWeb` (`src/game/RunHost.web.tsx`).
- **Input:** gesture-handler v3 `usePanGesture` (fires on threshold during the drag, not on release), keyboard
  arrows/WASD on web, optional on-screen buttons. One-action buffer + 120 ms cooldown in `player.ts`.
- **Audio/haptics:** `expo-audio` (procedurally generated original WAVs in `assets/sfx`, built by `/app/art_src/sfx.py`),
  `expo-haptics`. Audio init failures are swallowed → silent game.
- **Save:** `@/src/utils/storage` (AsyncStorage/localStorage). Versioned envelope `{v, sum, data}` with FNV-1a checksum,
  strict validation, migration hook (`MIGRATIONS`), temp-then-main safe write, marker key to tell "corrupt" from "fresh".
- **Backend:** FastAPI at `/app/backend` — Phase 1 exposes only `/api/health` and `/api/openapi.json`. Gameplay is 100% offline.

## Modules
```
src/game/          pure TS (unit-tested, no React/Skia imports)
  constants.ts     tuning (speeds, physics, gaps)
  player.ts        lane / jump / slide state machine + input buffer
  collision.ts     obstacle + coin tests
  spawner.ts       rule-based fair rows (never 3 trains; gap >= speed*0.95 s) + coin lines/arcs
  engine.ts        simulation, fixed 1/120 s sub-steps, object pools, event queue
  pool.ts, rng.ts, scoring.ts, projection.ts (2.5D pseudo-perspective math)
  renderer.ts      Skia drawing (only file touching Skia besides RunScreen)
  RunScreen.tsx    loop, phases (countdown/running/paused/crashed/over), HUD + overlays
src/save/          schema, checksum, saveManager, economy (bank-once by runId)
src/components/ui/ PrimaryButton, SecondaryButton, IconButton, CurrencyBalance, ConfirmationDialog,
                   LoadingOverlay, ErrorPanel, ToastMessage, PauseMenu, ToggleTile
```
Tests: `cd /app/mobile && npx jest` (player, collision/score/engine, spawner fairness + 4‑minute autopilot runs, save/economy).

## Why not Godot
Excluded by the product owner. Expo keeps one TypeScript codebase for game + future account/shop/ads/billing UI,
shares tooling with the website/admin, and Skia gives GPU-backed 2D drawing that is sufficient for a 2.5D runner.

## Android packaging (later, Phase 7)
EAS Build (managed by Emergent's Publish flow) produces APK/AAB from this project; `android.package` in `app.json`
is the stable application id. Skia, expo-audio and gesture-handler are all included in Expo Go and in EAS builds,
so no custom native code is required for Phase 1.

## Phase 2 additions

### Gameplay (pure TS, `src/game/`)
- **Speed curve** (`constants.ts → speedAt`): starts ~8.5 m/s, eases up smoothly; the first ~10 s only spawn easy single-lane barriers.
- **Trains & roofs**: trains are solid boxes (`TUNING.trainHeight` 2.6 m). `ramp` trains have a 7 m ramp in front of them; running up it lifts the runner onto the roof (`collision.surfaceHeight`). The player has real vertical physics (`player.ts`: `y`, `vy`, `support`, landing, fast-drop on swipe-down mid-air). Hitting the front of a train always crashes. `moving` trains roll toward the runner once they get within range, with blinking headlights and a red marker as a warning.
- **Spawner fairness** (`spawner.ts`): every row has at least one passable lane, moving trains get an extra reaction gap, and roof routes are only generated when you can reach them. An autopilot test drives thousands of metres with no crash.
- **Power-ups**: magnet, shield, speed (invincible), x2 score, hoverboard (from inventory, double-tap; absorbs one crash). Each lasts the time set in `TUNING.durations`.
- **Revive**: `engine.revive()` clears nearby obstacles, puts the runner back on the ground and gives 3 s of invulnerability. You can revive up to 2 times per run, paid in gems (`REVIVE_GEMS`).
- **Renderer** (`renderer.ts`, Skia): each world has its own colour palette for the track, plus rails, sleepers, ramps, train bodies and roofs, power-up pickups and a shield bubble. Graphics quality Low/Medium/High trims the detail.
- **Character rig** (`rig.ts` pure TS + `rigDraw.ts` Skia): a 2D cut-out skeleton (head, torso, pelvis, upper/lower arms, thighs, shins, shoes) seen from a three-quarter back view, drawn cel-shaded with outlines. The run cycle has 10 keyframes played at 12–15 keyframes/s (`runFrameRate`, scaled by speed) with interpolation. There are also takeoff/air/fall jump poses, a landing crouch, a duck/roll slide, a crash stumble and lean into lane changes. Each character has its own `rig` look in the catalogue. `/dev-rig` (dev only) renders a contact sheet of every pose for every character.
- **Roof readability**: trains are clipped just behind the runner (`TRAIN_CUT`), so the carriage's cut face shows its full height under the runner. The contact shadow stays on the surface and shrinks as the runner rises. The camera lifts/tilts slightly while on a roof. Roof routes are **scheduled** in normal play: the first arrives after 30 s, then one every 15–25 s (`Spawner.nextRoofZ`, `SpawnResult.roofRoute`), always with roof coins.
- **Interactive tutorial** (`tutorial.ts` + `/tutorial`): 7 steps (left, right, jump, slide, coins, dodge train, power-up). Each step freezes the run with an animated hand/arrow hint until the exact hinted action is performed; other inputs are ignored. Skip is always available. Replay from Settings grants nothing. The first run goes onboarding gift → tutorial → `/get-started` (character + board intro) → Main Menu.
  - *3D decision*: we stayed with Skia 2.5D. A 3D path using `expo-gl` + Three was not proven to work on both Android native and Expo web, so we did not adopt it.

### Persistence & economy (`src/save/`)
- **Save schema v2** (`schema.ts`) adds gems, XP, name, hoverboards, owned/equipped items, onboarding, daily streak, top-10 bests, ledger and event IDs. `MIGRATIONS[1]` upgrades v1 saves and keeps coins, best score, stats and settings.
- **Economy** (`economy.ts → applyTx`) is the **only** path for currency changes. It writes a ledger entry, rejects any event ID it has already seen (idempotency) and never lets a balance go negative. All of these go through it: run banking (`run:<id>`), purchases, daily rewards (`daily:<day>`), missions (`goal:<id>`), inbox gifts (`inbox:<id>`), revives (`revive:<run>:<n>`) and shop orders (`shop:<id>:<nonce>`).
- **Daily rewards** use a 7-day cycle based on the device's local date. Missing a day resets to Day 1, and a clock set backwards is blocked (`reason: "clock"`).
- **Missions & achievements** (`missions.ts`) take their progress from lifetime stats. Each can be claimed once.
- **Levels**: XP per run = distance/10 + coins. `xpForLevel(n) = 250 + 150(n−1)`.

### Config, services, i18n
- `src/config/catalog.ts` is the single catalogue for characters, boards, worlds (with palettes), power-ups, missions, achievements, shop, inbox, welcome gift, daily rewards and revive costs.
- `src/services/ads.ts` and `billing.ts` are **interfaces/stubs only**. Real-money products show `PurchaseStatusDialog` "Store not available yet", and ad actions are shown disabled as "Available soon".
- `src/services/music.ts` plays an original looping chiptune (`art_src/music.py` → `assets/sfx/music.wav`).
- `src/i18n`: English is complete. Hindi, Bengali, Tamil, Telugu, Kannada and Malayalam (the REQ-43 storyboard list) translate the core menu/onboarding strings and fall back to English for each missing key. Toasts are dismissed on every route change.
- `NetworkStatus` shows an informational offline banner (the game is fully offline). `ErrorBoundary` wraps the app. The save-failure banner on the menu offers a Retry.

### Dev flags (`__DEV__` only, Settings → Developer)
Grant 50k coins + 500 gems, simulate save-write failure, and mock clock offset ±1 day. On web you can also use `window.__RR_DEBUG__.placeCoinsAhead(n)` and `placeTrainAhead()`.
